# ADR-010：信号肽筛选不在本项目范围内，已拆为独立项目

状态：accepted（追认 2026-06 已生效的拆分）  
日期：2026-07-31（决策发生于 2026-06-04，本文为补记）  
关联：不替代任何既有 ADR。本文是一条**范围排除**记录——说明一件曾经在本仓库里做、后来移出去的事，以及为什么。

## 背景

项目早期在本仓库内做过信号肽相关工作：为目标蛋白挑选 / 设计分泌信号肽，建候选库、做相似序列聚类、选代表序列。这条线后来整体拆成独立项目（`SigScout`），本仓库不再承载。

拆分之后，本仓库里只剩下少量归档痕迹（归档目录默认不读）。结果是：**「这个项目做不做信号肽」在 active 文档里无处可查**——既没说做，也没说不做。将来有人问「为什么分泌工程项目不管信号肽」，没有出处。

## 决策

### 1. 信号肽筛选与设计不在本项目范围内

本项目回答的是「**改哪个基因**能缓解折叠 / 分泌容量瓶颈」，工作对象是代谢-分泌网络的化学计量与容量约束。信号肽回答的是「**用哪段前导序列**能让这个蛋白被正确送进分泌途径」，工作对象是序列特征与切割位点预测。

两者输入不同、方法不同、验证方式也不同：前者靠 LP 与模型约束，后者靠序列模型与实验切割验证。**放在一个仓库里只会让两条线互相拖慢，并让"这个系统能回答什么"变得说不清。**

### 2. 不使用 SignalP

信号肽预测的事实标准工具 SignalP **禁止商用**。本项目面向工业生产背景，合规是硬条件，不是偏好。

替代路线：从 UniProt 取**已实验验证**的宿主天然分泌蛋白信号肽作为已知数据来源，配合可商用的开源预测工具做评估。这条路线的代价是对全新 / 人工拼接序列的预测能力弱于 SignalP——接受，因为不可商用的工具在这个场景下等于不可用。

### 3. 边界维护方式

本仓库不再新增信号肽相关能力。若将来需要把 `SigScout` 的产出接进来，走**数据契约**（与 [ADR-005](005-rnaseq-expression-constrained-enzyme-capacity.md)、[ADR-006](006-carbon-source-condition-calibration.md) 同样的做法），而不是把那条线搬回来。

## 后果

- 正面：「这个系统能回答什么」的边界更清楚；两条线各自演进；合规约束有出处，不会有人再去评估 SignalP。
- 代价：跨项目协作成本；两处各有一套工程设施。
- 风险边界：本 ADR 只排除范围，不对 `SigScout` 内部的技术选型作任何决定——那属于那个项目自己的 ADR。
