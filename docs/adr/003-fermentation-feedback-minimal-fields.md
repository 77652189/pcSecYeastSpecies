# ADR-003：实验反馈发酵模板对齐现场真实记录结构，补最小必要缺口

状态：accepted
日期：2026-07-20
关系：独立决策，作用范围是方向 1（实验反馈闭环）自身的数据模板；不依赖、不替代 ADR-001/ADR-002

## 背景

现有 `python_pichia/src/pcsec_pichia/experimental_feedback/fermentation_template.py`/`schema.py` 的字段列表是早期设计的产物，包含大量现场并不实际记录的细粒度字段（精确温度/pH/转速数值、区分技术重复与生物学重复、系统内部 `prediction_run_id`/`evidence_id` 等），不是以研发组真实记录结构为基准设计的。

研发组实际在用的现场记录系统模板固定为 14 个字段（hLF/OPN 两个模板结构一致，仅数值量级不同，OPN 低一个数量级）：

- 表单级（2 个）：改造方案、发酵条件。
- 表格级（12 个）：本底菌株、发酵菌株（均从菌株库选取）、单克隆编号、72h-OD600、72h-UPR、72h-胞外产量(mg/L)、胞外 ELISA 稀释倍数、胞外是否超标曲、72h-胞内产量(mg/L)、胞内 ELISA 稀释倍数、胞内是否超标曲、备注（有无污染）。

用"判断某个基因改造有没有让分泌变好、好多少、多可信"这个目的倒推出的五条最小必要信息（改了什么；同批次匹配对照；结果+检测是否成功；候选对照采样时间点对齐；同一候选独立生物学重复数）作为**验证透镜**去检查这 14 个字段，结论是：**这 14 个字段本身已经基本覆盖最小必要信息，不需要另起一套精简模板**——"改了什么"对应"改造方案"；"结果+检测是否成功"由产量数值 + ELISA 稀释倍数 + "是否超标曲" QC 标记共同覆盖；"时间点对齐"由固定 72h 采样点覆盖。只确认缺一条：**改造是否已通过测序/PCR 等方式确认成功**——现有 14 个字段里没有这一条，不能把"没测出来"当真零。

## 决策

1. **以研发组实际在用的 14 字段现场记录结构作为方向 1 数据模板的参照基准**，不是另起一套独立的精简模板，也不是保留原有 `fermentation_template.py`/`schema.py` 中更重的既有设计。五条最小必要信息用于确认这个基准"够不够用"，不是用于替换它。
2. **补一条现有 14 字段中缺失的字段：改造是否已通过测序/PCR 等方式确认成功。**
3. 生物量指标确认按**原始 OD600 读数**记录（现场模板里的"72h-OD600"字段本身就是这个形式，如果稀释了要额外记稀释倍数）；换算干重由系统统一、版本化管理，不由人工换算引入误差，也不要求现场模板本身改动。
4. `fermentation_template.py`/`schema.py` 中不在这 14 字段结构里的细粒度字段（逐行精确温度/pH/转速数值、显式区分技术重复与生物学重复等）需要重新评估是否保留：这些字段不是"以后再按需加回的精简候选"，而是从一开始就不在研发组真实记录范围内的过度设计，应在实现时明确判断去留，不能默认保留。

## 明确保留待定、不在本决策中假设答案的问题

- "对照"提交如何与"候选"提交配对匹配（是否依赖自由文本的"发酵条件"字段，匹配是否可靠）。
- "单克隆编号"是否是同一个物理克隆长期唯一的编号（跨多次发酵不变），还是每次提交重新分配。

这两条需要看研发组实际提交的真实数据后才能确认，本决策不预设答案，留待真实数据到来后单独确认。

## 不变量

- 实验反馈闭环保持被动接收既有历史数据的定位：系统不主动设计、要求或建议湿实验做什么，湿实验测什么完全由研发组自己决定。对外沟通和 UI 文案应使用"历史数据核对/事后复核"一类表述，避免"校准环节/校准闭环"这类暗示系统会根据实验结果自动调整预测的说法；`calibration.py` 模块名和内部字段名不因此改动。
- 模板调整不改变已导入历史数据（旧 `schema_version`）的有效性判定；如需要字段迁移路径，须显式声明版本变更，不得静默改变历史数据解释。
- 实验数据导入不会自动修改 recommendation tier、curated evidence 或模型约束，这条既有边界不因模板改版而改变。

## 影响

优点：模板与研发组实际记录习惯完全对齐，降低导入摩擦和字段误填风险；新增"改造确认"字段堵住一个真实的验证缺口；不需要另建一套精简模板与现场结构并存。代价：现有 `fermentation_template.py`/`schema.py` 中一部分已实现但不在 14 字段结构里的细粒度字段需要明确去留，需要单独盘点哪些是"过度设计、现场本来就不记录"、哪些是不应动的既有能力（如 prediction linkage 相关字段），不能不作区分就一并移除。
